## 一、怎么跑（由快到慢）

| 层 | 在哪儿跑 | 命令 | 证明什么 |
|---|---|---|---|
| 1 一致性 | 文档仓库根 | `python3 tools/verify_url_contract.py` · `python3 tools/verify_knowledge_base.py` · `python3 tools/gen_knowledge_base.py --check` · `python3 tools/gen_agent_entries.py --check` | 接口文档、知识库、生成页、入口文件与代码一致（秒级） |
| 2 前端 | 小程序仓库 | `node --test 'tests/*.test.js'` | 小程序页面与工具函数（秒级） |
| | 控制台仓库 | `node --test 'tests/*.test.js'`；`for f in assets/*.js; do node --check "$f"; done` | 控制台调的路径、方法、权限点在后端都存在；语法 |
| 3 改动的模块 | `代码/hengde-volunteer-parent` | `./mvnw test -f ../hengde-volunteer-<模块>/pom.xml` | 该模块的服务层规则 |
| 4 **全量（发版前必跑）** | 同上 | `./mvnw clean install -fae`（约 17 分钟） | 全部 14 个模块 + api 的 HTTP 全流程；看 Reactor Summary 列全 15 行 |
| 5 压测（动了并发 / 锁时） | 同上 | 见 [`横切/测试纪律.md`](横切/测试纪律.md)「压力测试命令」 | 并发下账目守恒、不死锁 |
| 6 线上（发版后） | 文档仓库根 | **只读、不要账号**：`python3 tools/online_smoke.py --base <线上>/api --expect-build-time <发版手册 1.1 步的值>`（约 1 分钟）<br>**要登录、会写库**：`python3 tools/miniprogram_acceptance.py seed / verify / cleanup --base <线上>/api`（用你自己的 token） | 前者：新包、迁移号与本地一致、280 个 GET 匿名都被拒或放行得对、零 5xx、回调路由可达、控制台资源是新的、doc.html 屏蔽；后者：小程序验收单逐项留证据 |

- 第 3、4 层要本机 Docker；仓库在 iCloud 桌面上时，先 rsync 到临时目录再跑（排除 `target/` 与「* 2*」冲突副本）。
- 单独跑绿 ≠ 全量跑绿：api 的 HTTP 用例会起多个 Spring 上下文，批次收尾一定跑第 4 层。
- 第 5 层压测**只在本机跑**（Testcontainers），绝不对线上压。死锁类失败先拿 InnoDB 的死锁报告再改（方法见 [`横切/并发与锁.md`](横切/并发与锁.md)）；赛跑类用例一次过不算数，失败过的要连跑几次。
- 本机挂着 HTTP 代理时，`online_smoke.py` 默认直连（经代理每个请求多 2–4 秒、会超时），要走代理加 `--use-proxy`。

## 四、已知缺口

- **核心活动链没有 HTTP 全流程用例**：签到签退 → 秘书确认 → 积分 → 活动证书，只有服务层用例（S）；接口层只被 GET 冒烟碰到。改这条链时要多跑 activity 与 honor 模块，并在线上用 `miniprogram_acceptance.py` 核对。
- **本地联调默认连线上**：控制台 `index.html` 与小程序 `app.js` 都指向线上服务器；做写操作的回归前先改成本机后端（控制台用 `tools/serve_admin_local.py`）。

- **公益捐书装箱偶发死锁（未修）**：`BookDonationApiStressTest` 21 次里 1 次 `POST /a/donate/boxes/{id}/pack` 回 500（`DonateItemMapper.packIntoBox` 死锁）。
  那条 UPDATE 按唯一键 `exclusive_code` 定位，按理只锁一行；没抓到 InnoDB 死锁报告，不靠猜改。下次复现时先抓报告（测试里加 `SHOW ENGINE INNODB STATUS` 的输出）。
- **线上域名**：`xcx.hdzyz.com.cn` 2026-10-17 在本机解析不到（NXDOMAIN），线上检查只走了 IP。

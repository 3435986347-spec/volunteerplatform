# 测试纪律

> 变异验证、并发用例与全量回归的纪律。测试基座（`@SpringBootTest` + Testcontainers、领域模块的测试启动类、分页拦截器只在 api）见根 `AGENTS.md`。
> 2026-10-17 从《约定与踩坑》按主题拆出；一条一节，先说规则、再说为什么 / 撞过什么。

## 变异验证必须 clean 构建

**变异验证必须 clean 构建（2026-09-17 撞出）**：变异脚本用 rsync 把源码还原回去时保留的是原来**更旧**的修改时间，而上一条变异编出来的 class 更新——`install` 的增量编译认为无需重编，**上一条变异就悄悄留在了下一条的 jar 里**。那一轮里好几条变异「必红」其实是被上一条的残留弄红的（活动补全批的「资格档案改回快照读」clean 复验时**存活**，补了代报名用例才红）。变异脚本里的构建一律 `clean install`；判读结果时，报错若与上一条变异一字不差，先怀疑残留。

## 变异验证每次要重装本轮动过的所有模块

**变异验证：每次要重装「本轮动过的所有模块」，不只是这一条改的那个（2026-09-18 撞出）**：爱心企业批商品段的变异跨 donate 与 enterprise 两个模块，脚本每条只 `install` 被改的那一个，于是上一条变异的 jar 一直留在本地仓库里——后面几条变异的「必红」其实是上一条的效果（失败信息与上一条一字不差，正是那个信号）。跨模块的变异集，`runmut` 要么整反应堆 `install`，要么把本轮涉及的模块逐个重装。与下面那条 clean 构建是同一类错误的两种形态。

## 赛跑类并发用例要断言每种结局都出现过

**赛跑类并发用例要断言「每种结局都真的出现过」**：不偏置起跑时一方几乎总是赢（加锁读先到的那方），另一条分支一次都没跑到，用例照样全绿——`TradeBizEntryTest` 第一版就是 30:0。偏置三分之一先 A、三分之一先 B、三分之一同时，再 `assertTrue(aWins > 0 && bWins > 0)`。

## 两条入口汇到同一段逻辑时，用例要分别走到每一条入口

注销冷静期那批的变异「`isDue` 不认禁用账号」第一轮**存活**：禁用用例只走了定时收尾，而收尾直接调按 id 落定的 UPDATE、根本不经 `isDue`；补了走登录路径（`selectByPhoneHash` → `finalizeIfDue`）的用例才红。

## 全部 GET 端点的冒烟用例是必跑的

`GetEndpointSmokeApiTest` 从 `RequestMappingHandlerMapping` 枚举全部 GET 端点，用未登录 / 游客 / 已实名且验过手机号 / 无权限子账号 / 超管 / 企业逐个打（路径变量填不存在的 id），断言零 5xx——新加的端点自动纳入。

## 单独跑绿 ≠ 全量跑绿

api 的 HTTP 用例按 properties 起多个 Spring 上下文，Sa-Token 的静态状态由测试专用的 `SaTokenContextRebinder` 指回当前上下文；批次收尾要跑一次 api 全量。仓库在 iCloud 同步的桌面上时，构建与测试放到临时目录的镜像里跑（rsync 排除 `target/` 与「X 2」冲突副本），见根 `AGENTS.md`。

## 压力测试命令

压测用例打 JUnit `@Tag("stress")`，surefire 默认排除；**排除优先于包含，所以两个参数都要给**。服务层几十到几百线程、断言各本账守恒；HTTP 全链路在 api 模块用 RANDOM_PORT 起真 Tomcat + Testcontainers。在 `代码/hengde-volunteer-parent/` 下执行：

```bash
#     服务层：几十到几百线程，断言四本账守恒；HTTP 全链路：api 模块 RANDOM_PORT 起真 Tomcat + Testcontainers
./mvnw test -Dtest.excludedGroups=none -Dgroups=stress -f ../hengde-volunteer-donate/pom.xml
#     donate 的 stress 类：MallCouponStressTest / BookDonationStressTest / WishStressTest / PairStressTest / LogisticsPushStressTest / MallExpressStressTest / DonationStressTest
./mvnw test -Dtest.excludedGroups=none -Dgroups=stress -f ../hengde-volunteer-trade/pom.xml
#     trade 的 stress 类：TradeStressTest（回调 / 查单 / 扫描三路同时写回同一笔支付 + 并发退款）
./mvnw test -Dtest.excludedGroups=none -Dgroups=stress -Dtest=FormStressTest -f ../hengde-volunteer-organization/pom.xml
./mvnw test -Dtest.excludedGroups=none -Dgroups=stress -Dtest=ComplaintStressTest -f ../hengde-volunteer-data/pom.xml

./mvnw test -Dtest.excludedGroups=none -Dgroups=stress -Dtest=SocialStressTest,SocialGovStressTest,SocialChatConcurrencyTest -f ../hengde-volunteer-social/pom.xml
./mvnw test -Dtest.excludedGroups=none -Dgroups=stress -Dtest=EnterpriseConcurrencyTest,EnterpriseSponsorConcurrencyTest,EnterpriseSocialConcurrencyTest -f ../hengde-volunteer-enterprise/pom.xml
```

## Testcontainers 的两个环境坑

- **Docker api.version**：docker-java 默认 API 版本可能低于本机 Docker Engine 的 `MinAPIVersion`，报 HTTP 400。父 POM 的 surefire 已配 `-Dapi.version=1.43`（系统属性；环境变量 `DOCKER_API_VERSION` 无效），不用写死 TCP 端口。
- **用到 Redisson 的模块要额外的 Redis 容器**：starter 装配的 `RedissonClient` 在 bean 创建时就连 Redis，所以 activity、organization 以及经 activity 传递引入 starter 的模块，每个 `@SpringBootTest` 都要 `@Import(RedisTestcontainersConfig.class)`；common / auth / publicity 只要 MySQL。

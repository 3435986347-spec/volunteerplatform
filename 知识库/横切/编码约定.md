# 编码约定

> 跨模块的写法约定。依赖注入、测试基座、URL 路径、技术栈的硬规矩在根 `AGENTS.md`；这里是补充。
> 2026-10-17 从《约定与踩坑》按主题拆出；一条一节，先说规则、再说为什么 / 撞过什么。

## 模块边界以根文件为准

设计文档（`文档/业务领域划分.md`、`文档/志愿者小程序开发.md` 等）已统一为**领域垂直切分**口径；个别处与根文件有出入时，**以根文件和代码为准**。

## 写 Controller 前先查接口契约

端点表分在 `文档/v1/url文档v1.md` 到 `文档/v4/url文档v4.md` 四份里（v1 是冻结的历史快照，v2–v4 受契约脚本核对）；按模块的现行清单见 [`生成/接口索引.md`](../生成/接口索引.md)。改完跑 `python3 tools/verify_url_contract.py`，再用 `javap -p` 确认方法真的在编译产物里（注释吞掉端点时 `mvn` 与契约脚本都曾放过）。

## 状态 / 角色码收在 `constant` 持有类

**状态/角色魔法数已收敛到 `constant` 持有类**（单一来源、零行为变化）：跨服务复用的码集中在各模块 `constant` 包——activity 的 `ActivityStatus`（含发布态 4/5 与 `isUnderReview`）/`EnrollmentStatus`/`AttendStatus`/`RunStatus`/`SecretaryStatus`/`PointsStatus`/`PointsFactor`/`LeaderType`/`AuditStatus`，organization 的 `MemberStatus`/`MemberRole`/`GroupStatus`/`SquadApplyStatus`；service 引用持有类常量而非自定义私有魔法数。仅单服务自用的语义码（`CHECKIN_METHOD_*` / `VIOLATION_*` / `CHANGE_*` / `OP_TYPE_*` 这类服务内私有常量）保持就地定义。新增状态判断时优先复用/扩展持有类，勿重新散落魔法数。

# 领域四 · 公益捐赠（捐书 · 微心愿 · 结对 · 众筹 · 在线捐款）

> **主要模块**：donate · **也涉及**：trade（收付）、honor（捐赠证书）、data（捐赠数据汇总）、auth（实名、PII 查询）。
> 本页是**业务口径**；代码不变式见 [`模块/donate.md`](../模块/donate.md)、[`模块/trade.md`](../模块/trade.md)。状态截至 2026-10-17。

## 现行规则

### 物资流转（捐书、微心愿、众筹捐物共用一套地基）

- 运单 / 物资 / 箱子 / 轨迹都带「来源类型 + 来源 id」：1 捐书活动（id＝活动）、2 微心愿（**id＝认领**，不是心愿）、3 众筹捐物（id＝项目）。来源名统一由 `DonateSourceTitleService` 解析。
- **公益捐书十步**：捐赠人一次提交「物资 + 快递公司 + 单号」（须实名；一个单号只登记一次，取消即释放）→ 扫码到货 → 核对（不合格须写原因）→ 给合格物资生成专属码 → 建箱 → 扫码装箱 → 送达受赠单位。三级码前缀不查库就能分流（物品 `HDI…`、箱 `HDB…`），扫码页先识别再做动作。
- 不合格退回：捐赠人交退回地址（电话密文）→ 后台按运单登记寄回。流转轨迹对捐赠人公开。
- 后台：商品条码库、受赠单位主数据（学校 / 乡镇 / 其他，XH46）、10 维搜索与导出（上限 20000 行，超了报错不截断）、「本次活动数据」只算合格物资、按统计截止时间。
- 物流：快递100 **只买了查询**（XH48）——轨迹在有人打开时按刷新间隔去查、快照落库，定时轮询默认关；订阅推送代码在、默认关、没端到端验过。

### 微心愿

- 心愿池 / 已认领 / 已实现三个页签；**看详情要已验证手机号，并记录查看人**（一人一个心愿一行，号码密文快照，后台看得到，XH43）；认领要已实名。
- 受助人姓名与学校**密文存储**，志愿者端打 *，**只有当前认领人**看全文；内部备注、发放照片同理。
- 一个心愿至多一条有效认领；能不能取消认领按「物资还活着吗」判（全部不合格的包裹不算）。
- **实现心愿**：没有未到货 / 未核对的包裹、至少一件合格物资、合格物资都已生成专属码 → 存 1–9 张发放图片、通知认领人、**出捐赠证书**。
- 后台批量导入全成或全不成（逐行报错）；上报单位按名称对上受赠单位，对不上报错。排行按**已实现**的心愿数（XH44）。

### 助学助困（结对）

- 项目四个页签；项目展示**受助人信息**（姓名 / 性别 / 年龄 / 学校 / 年级 / 上报单位，姓名学校密文、志愿者端打 *，**只有这个项目上已成立结对的人**看全文）和**活动动态**（发放凭证，公开）（XH40）。
- 登记（指定金额或全款）→ 协会确认结对成立 → **出捐赠证书**（正文写「结对成功」、不写金额，XH17）；取消已成立的结对会撤销证书。
- **两本账**：认捐额（确认成立时累加，上限写在累加语句里）与到账额（付款到账才计入、退款减回）；结对捐款付「认捐额 − 已付」。
- 付过款的结对**志愿者不能自己撤回**，由协会取消后原路退款（XH41）。受助方来信分公开信与私信（私信只写给已成立的结对）。

### 众筹

- **每个项目只收一种**：捐款或捐物（XH38）；只收物的项目可不填预计金额；改造前两样都收的项目照常运行，后台再编辑时必须选一种。
- 捐款：金额自填、单笔上限 5 万元、待支付 30 分钟（XH47）；已筹＝到账之和；公开捐赠记录只列已到账、姓名留首字。捐款**到账即出证、退款即撤销**。
- 捐物：登记寄出的物资 + 快递，走物资流转；**核对出合格物资时出证**（一个包裹一张，件数只数合格的；补录 / 移除物资会补证或撤证）。

### 在线捐款与发票

- 付款统一走 trade：小程序传 `wx.login` 的 code，openid 由服务端现换；付款截止同时传给 trade；事件 + 补偿任务双保险（事件丢了照样到账、超时但渠道收到钱的不取消）。
- 退款**先改账、提交后再原路退**，退款失败不回滚、原因落库供重试；已登记开票的捐款不能直接退（先在系统外作废）。
- 发票：提交时记抬头与税号；**财务在后台上传开好的发票文件**（私有存储，再传即替换），捐款人在小程序下载（短期链接），捐款显示「已完结」（XH42）。
- 「我的捐赠记录」只含众筹的捐款与捐物（库里合并分页）；结对在结对中心。

### 捐赠证书与统计

- 所有捐赠都出证（XH17），只用**捐赠样本**，缺样本拒绝出证（XH16）；来源键在 `DonateCertRefs`，够格口径与正文在 `DonateCertificateQueryService`，经事件交给 honor。
- 「修建书屋数」＝收到过捐书物资（已送达）的受赠单位数，同一所学校多次只算一间（XH45）。

## 已知限制与待办

- **小程序还没有微心愿、结对、众筹、捐书页面**：首页这几个入口显示暂未开放，后端接口齐全。
- **微信支付从未真实调用过**：域名备案后先走一遍 1 分钱「下单 → 付款 → 回调 → 查单 → 退款 → 对账」（XH49）。
- 捐赠证书没有定时补偿（活动证书有），人工救济是幂等的单条补发端点。
- 原型 P50 / P54 / P56 的「惊喜日期」含义未答；众筹不做报名形态，暂不涉及。
- Row 70「仓库管理系统」冻结（XH52）。

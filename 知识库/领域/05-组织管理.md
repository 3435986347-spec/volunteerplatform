# 领域五 · 组织管理（部门 · 小组 · 分队 · 架构 · 权限 · 问卷 · 考试）

> **主要模块**：organization · **也涉及**：auth（管理团队标记的写入、后台账号）、activity（代报名、临时负责人的报名优先）、data（投诉按部门路由）。
> 本页是**业务口径**；代码不变式见 [`模块/organization.md`](../模块/organization.md)。状态截至 2026-10-17。

## 现行规则

- **部门**：理事会 + 组织部 / 秘书部 / 宣传部；**监察部、分队管理部已撤销**（XH01）。部门没有主数据表，是后台账号上的一段文字（`admin_user.department`）——按部门授权、投诉路由都要求**一字不差**。
- **后台权限**：每位管理成员一个子账号，超管逐个勾权限点（现行 99 个，见 [`生成/权限点.md`](../生成/权限点.md)）；`user:edit`、`org:perm-assign` 两个高危码**写死仅超管、不入权限表**。协会说「审核＝该部门成员都能操作」，上线时按部门授（XH03），但系统没有「部门继承权限」，换届要人工补授。
- **志愿者端权限**：只授给「活跃且 `manager_flag=1`」的志愿者，可授的点由白名单圈定；停用或取消管理团队即时失效。管理团队志愿者凭授权在小程序发布活动（进后台审核）。
- **管理团队**：后台手动设 / 取消标记（落审计）；或志愿者提交「报名管理团队」申请（固定表单，或后台为该场景发布了问卷时连同答卷提交）→ 后台审核通过即置标记（**不自动授权限点**）；可批量导出申请。
- **志愿小组**：志愿者自由发起并命名、发起人默认组长；**发起扣 50 积分、组建被驳回退回**（XH53）；志愿者端小组列表标出「我」在每个组的状态（已加入 / 审核中 / 可申请）；组长设管理员（≤3 人）、移除成员、审批加入；**一人只能在一个小组**；同小组成员可互相代报名活动；后台批量导入（视同审批）、解散、组建审核、组长转移与变更历史。
- **分队**：学校 / 乡镇等类型后台自定义，每类型人数上限；未归属看负责人信息、已归属看同分队名单（可见字段可配）；**加入申请由分队负责人在小程序审，也可由部门在后台审**（XH27），两条路串行化；负责人在后台分队表单里用志愿者选择器指定，**撤换负责人或停用分队即刻收回审核权**——原负责人正在点的批准 / 拒绝也落不了库；停用的分队志愿者端不可达。
- **组织架构**：节点＝部门，后台增删改（最多 10 层、不能成环、有下级或有人的节点不能删）；人放在节点上带职位，一人一个位置；名字下面一行「部门 · 职位」接进我的资料与志愿者管理；电话只给已实名的查看者。理事会节点由 V101 补种在协会根节点下、排在组织部前面（XH04），成员由超管在后台放进去。
- **问卷引擎**：七种题型（单选 / 多选 / 判断 / 填空 / 简答 / 文件 / 日期）；发布后题目冻结；一个场景同时只有一份在收集；可设每人一次；文件题只收本系统上传；答卷导出 xlsx。场景：1 通用、2 报名管理团队、3 评优评先、4 意见反馈（不进问卷列表）、5 投诉建议附带。
- **活动临时负责人考试**：同一时刻一份开放的试卷；客观题交卷即判（多选全对才得分），主观题后台人工阅卷；达分获资格，**资格按时间现算**；组织部可撤销资格（须写原因）、导出名单。资格影响报名开放时间、名单排序与「我的」所属职务。

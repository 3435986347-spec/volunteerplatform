## 现行规则

- **场次制**：一个活动有多个时间段（场次），名额在场次上；**场次是参与的最小单元**——报名、签到签退、考勤、违规、证书都按场次（XH13）。
- **发布**：后台直发即上线；小程序（管理团队志愿者凭授权）提交的活动**进待审**，后台 `activity:publish-audit` 审核后才上线；待审 / 驳回的活动不接受任何常规写动作。支持复制、固定日期周期发布（显式日期 ∪ 周几规则，整批全成或全败）、历史活动（只作补录载体，志愿者端不可见）。
- **报名**：资格条件（年龄 / 年级 / 性别 / 已参加次数与时长 / 报名项目数上下限）、**全平台同时段冲突**（只算活动还在的时段，已取消 / 已删的活动不占）、处置闸门、**三档开放时间**（管理团队 / 临时负责人 / 普通志愿者；角色那一档留空＝没有提前）、报名范围（全平台或指定一个分队）。同小组成员可互相代报名，资格按每个被代的人各自判。
- **报名和取消都按场次（XH55）**：已报的场次不能重复报，同一活动的其它场次可以补报，项目数上下限按一共报的场次算（代报名按被代的人算，后台补录不看上下限）。取消指定场次，一场时直接确认，多场可取消时勾选、默认勾当前卡片；签到过的场次不能取消；取消后剩下的场次不能低于下限，要么一起取消。
- **现场负责人**：报名本活动的志愿者或管理团队志愿者（未报名也可），不占名额，积分 ×1.4；后台账号也可当负责人。
- **签到签退**：扫负责人出示的码 + GPS（Haversine 距离 ≤ 半径）双因子，时间窗按**场次起止**；负责人可手动确认、标记到位（正常 / 请假 / 迟到 / 缺席）、统一签退；结束后志愿者确认到家（详细地址只对 `activity:home-address` 下发）。
- **时长与积分**：秘书部确认考勤后才汇入服务记录、发积分；积分＝基数 × 角色倍率（负责人 1.4、管理团队 1.2）× 违规系数（正常 1 / 减半 0.5 / 不发 0），**0 分也发通知**；积分写进账本（领域三）。组织部改签到 / 签退 / 积分要部长二次审核；补录（已发布活动或历史活动）要部长审核，历史活动补录只记时长不发积分。
- **违规**：现场负责人记录 / 组织部巡查 → 组织部审核；**审核通过才对志愿者可见**、才够格开奖惩单（「通过」不等于「处罚」，见领域八）。
- **报名要先实名**：游客不是志愿者，本人报名、同组代报名、后台手动录入都不行（[XH54](../决策/协会决策.md)）。
- **名单公示**：组织部确认名单 → 活动开始前公示；按场次、只列已通过、管理团队在前；普通成员电话打 *，负责人全显示（游客看负责人也打 *）。
- **评价**：志愿者评活动与负责人（须实际签到）；负责人评志愿者；活动总结（须已结束）。
- **相册**：活动自动建册「编号 活动名称」；只有报名已通过的人 / 本活动负责人 / 管理团队能传；上传积分由审核时还在的张数算、每人每相册有上限（来源类型 ALBUM）；删相册 / 删照片 / 批量下载各一个权限点；可同步到社区。
- **提醒**：活动开始前定时提醒、活动取消、活动结束邀评走通知短信（领域十一「通知」）；三种都属活动类，志愿者可以在订阅通知里关掉（XH21）。

## 已知限制与待办

- 「扫一扫」统一入口、积分中心页等小程序页面见 `文档/小程序待做页面-2026-09-29.txt`。
- **Row 65 活动修改没做全**：`ActivityService.update` 只要有人报名就整个拒绝。需求是开始前可改时间、资料、人数、截止时间，开始后可改人数、结束时间、招募截止、岗位结束时间。要先把时间段从全量替换改成按场次增改删，已有报名的场次不能直接删。
- **Row 65「提前生成公示则公示时截止」没做**：确认名单写了 `roster_publish_time`，`EnrollmentService` 不看它，确认后还能报。
- **Row 30 / 原型 P91「待录取」没数据**：`MyActivityService.myActivities` 只列已通过的报名，待审核的人在「我的活动」看不到、也取消不了。
- **Row 74 活动评价、负责人评价、志愿者评价后台看不到**，也不能删除、屏蔽；商品评价、赞助商评价已有。
- **Row 69「各数据界面批量下载」只做了一部分**：报名名单、志愿者、企业、问卷答卷、微心愿、捐书物资能导出；服务记录、积分明细、商城兑换单、奖惩还不能。
- 证书的 `ck_cert_activity_scope` 要求活动证书必须挂场次：将来出现「有活动、无场次」的真实数据时会挡住上传。

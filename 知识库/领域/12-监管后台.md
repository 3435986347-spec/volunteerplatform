# 领域十二 · 监管后台（SaaS 多组织）

> **未建**。这是独立于 `hengde-volunteer-api` 的平台级应用（运营方控制台），凌驾于各组织实例之上。状态截至 2026-10-17。

## 现行口径

- **多组织部署＝白标多实例**：每个社会组织一套独立部署（独立库 + 独立配置，跑同一份 api 制品）。单个实例内部是单体还是微服务与此无关——**不要按多租户改造单实例的表结构**。
- 运行机制已支持「同一份制品、不同配置」；**一键开通的控制台没有**。

## 需求清单（全部 ⬜）

| 功能 | 需求原文（要点） |
|---|---|
| 多系统部署 | 一键为新社会组织开通 / 部署同款小程序及后台 |
| 系统账号管理 | 各组织后台账号密码、有效期、权限 |
| 增值功能收费 | 按年分配短信 / 存储 / 身份证校验额度，超额追加购买 |
| 数据管理 | 汇总监管各组织实例的数据与使用情况 |
| 切换账号 | 切入任意组织后台 |

## 需求出处

[需求表](../需求/需求表.md) Row 82–Row 86（监管后台）。

## 开工前要想清楚的

- 「切入任意组织后台」与「数据管理」都要跨实例访问：各实例是独立库，需要一条受控的运营方通道（不是共享数据库）。
- 增值功能额度（短信、存储、实名核验）现在都是各实例自己的第三方账号与配置，计量要从各实例上报。

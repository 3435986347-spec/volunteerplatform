# 领域十二 · 监管后台（SaaS 多组织）

> **未建，V5 规划已完成、尚未开工**。这是独立于 `hengde-volunteer-api` 的平台级应用（运营方控制台），凌驾于各组织实例之上。状态截至 2026-11-18。

## 现行口径

- **多组织部署＝白标多实例**：每个社会组织一套独立部署（独立库 + 独立配置，跑同一份 api 制品）。单个实例内部是单体还是微服务与此无关——**不要按多租户改造单实例的表结构**。
- 运行机制已有「同一份制品、不同配置」的基础，但品牌名称、短信签名与初始化种子仍有恒德专属内容；**一键开通的控制台没有**。
- **规划边界**：控制面独立应用、独立库与登录态；组织侧连接器主动出站上报 / 领取命令，控制面不直读组织业务库，也不给现有业务表加租户字段。

## 已确认执行决策（2026-11-18）

以下是本次阶段规划时确认的 V5 执行口径；具体人员、真实账号与秘密不进知识库。

- **Q1 运营权限**：部署、收款、切换、审计分角色授权；人员可以兼任，但权限不合并。具体运营人员在部署时登记。
- **Q2 “内存”含义**：指对象存储容量，按对象实际占用字节数计量；服务器内存只做运行监控。
- **Q3 年度周期**：按每个组织的开通周年计算，追加额度包各自记录有效期。
- **Q4 超额行为**：V5 只预警、不硬拦截；未来若需停止短信、实名或上传，逐指标另审实时预留、并发和离线策略。
- **Q5 订单与定价**：V5 逐单人工定价、人工收款登记，不内置固定价目和在线支付；订单记录金额、收款人与凭证说明。未来在线收费前仍须明确收款主体、退款与发票规则。
- **Q6 切换后台**：默认关闭、独立解锁，不阻塞 V5 主体；将来批准后首版也只读，并需单独安全评审。
- **Q7 账号到期**：禁止新登录、撤销已有会话并停用，恢复必须重新授权。
- **Q8 监管指标与频率**：首屏采用 V5 规划 D5 的聚合指标与运行状态；分钟级心跳、日级业务指标。
- **Q9 新组织资料**：小程序主体、AppID、域名和第三方账号由组织方提供；V5 自动开通服务端与后台，微信侧办理保留为检查单。
- **Q10 数据保留**：组织退出、欠费或停用后不自动删库，导出与销毁另行审批；具体审批人和流程在正式运营前写入运营手册。

## V5 规划与开工门禁

完整设计见 `文档/v5/V5规划.md`（D1–D12、Q1–Q10、数据模型、批次完成定义与验收），逐阶段执行卡见 `文档/v5/V5阶段执行规划.md`；本页维护现行口径与已确认决策，不复制第二份阶段细节。

- **前端页面同样受[原型还原门禁](../跨端/前端原型还原.md)约束**：新建或改结构前先定位需求与 PDF 对应页并实际查看，图标先提取内嵌原图、失败才裁剪。监管需求没有对应视觉页时须登记原型缺口与确认依据，不虚构页码或资源；这条门禁不代表监管后台已开工。

- **主体执行序**：前置与契约 → 控制面地基 → 只读监管 → 白标开通 → 组织账号 → 用量计量 → 配额订单 → 验收运营。
- **独立解锁**：切换账号批须先答 Q6；即使批准，首版也只读，不提供写权限，未解锁不影响 V5 主体其余批次。
- **明确后置**：真实在线收费与付费调用硬拦截不在 V5；V5 只做计量、预警、额度包流水与人工订单。
- **迁移边界**：控制面自己的库有独立 Flyway 序列；组织侧连接器若需落业务库，仍只在 common 领号，开工时跨分支查最大号（当前快照下一个为 V102）。
- **数据边界**：只收聚合指标与运行状态，不汇聚志愿者 PII；组织账号密码不可读，部署秘密由 worker 直接写入目标实例受控配置，不进控制面业务库。

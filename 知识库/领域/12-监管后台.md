# 领域十二 · 监管后台（SaaS 多组织）

> **未建，V5 规划已完成、尚未开工**。这是独立于 `hengde-volunteer-api` 的平台级应用（运营方控制台），凌驾于各组织实例之上。状态截至 2026-11-18。

## 现行口径

- **多组织部署＝白标多实例**：每个社会组织一套独立部署（独立库 + 独立配置，跑同一份 api 制品）。单个实例内部是单体还是微服务与此无关——**不要按多租户改造单实例的表结构**。
- 运行机制已有「同一份制品、不同配置」的基础，但品牌名称、短信签名与初始化种子仍有恒德专属内容；**一键开通的控制台没有**。
- **规划边界**：控制面独立应用、独立库与登录态；组织侧连接器主动出站上报 / 领取命令，控制面不直读组织业务库，也不给现有业务表加租户字段。

## 需求清单（全部 ⬜）

| 功能 | 需求原文（要点） |
|---|---|
| 多系统部署 | 一键为新社会组织开通 / 部署同款小程序及后台 |
| 系统账号管理 | 各组织后台账号密码、有效期、权限 |
| 增值功能收费 | 按年分配短信 / 存储 / 身份证校验额度，超额追加购买 |
| 数据管理 | 汇总监管各组织实例的数据与使用情况 |
| 切换账号 | 切入任意组织后台 |

## V5 规划与开工门禁

完整规划见 `文档/v5/V5规划.md`（D1–D12、Q1–Q10、数据模型、批次完成定义与验收），本页不复制第二份。

- **主体执行序**：前置与契约 → 控制面地基 → 只读监管 → 白标开通 → 组织账号 → 用量计量 → 配额订单 → 验收运营。
- **独立解锁**：切换账号批须先答 Q6；即使批准，首版也只读，不提供写权限，未解锁不影响 V5 主体其余批次。
- **明确后置**：真实在线收费与付费调用硬拦截不在 V5；V5 只做计量、预警、额度包流水与人工订单。
- **迁移边界**：控制面自己的库有独立 Flyway 序列；组织侧连接器若需落业务库，仍只在 common 领号，开工时跨分支查最大号（当前快照下一个为 V102）。
- **数据边界**：只收聚合指标与运行状态，不汇聚志愿者 PII；组织账号密码不可读，部署秘密由 worker 直接写入目标实例受控配置，不进控制面业务库。

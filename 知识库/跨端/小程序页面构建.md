# 小程序页面构建：从原型到接口验收

面向志愿者端原生微信小程序。这里只规定**怎么搭页面、复用什么、怎样对齐接口**；业务字段、流程和权限仍以[领域页](../领域/)、[协会决策](../决策/协会决策.md)及实际代码为准。

下文的小程序路径均相对 `volunteerplatform-miniprogram/` 仓库根。完整工作区中它与文档仓库同级，即文档仓库的 `../volunteerplatform-miniprogram/`；单独克隆时先按本仓库 `AGENTS.md` 找到知识库。

> **所有前端共用的硬门禁**：[前端原型还原](前端原型还原.md)。新建或改结构前必须渲染并实际查看 PDF 对应页，图标先提取 PDF 内嵌原图、失败才按页面裁剪；本页不复制第二份规则。

## 1. 动手前的输入与边界

1. 先读对应 `知识库/领域/*.md` 的现行规则、功能状态和待办；涉及需方口径时查 `知识库/决策/协会决策.md`，不要只凭原型猜测流程。
2. 用 `知识库/需求/需求表.md`、`知识库/需求/原型.md` 定位 Row 和原型页，再打开 `文档/志愿平台设想【第十版】.pdf` 核对视觉与图标。**原型文字索引是生成物，不手改，也不能替代 PDF 视觉核对。**
3. 在 `知识库/生成/接口/<模块>.md` 确认接口方法、路径和权限，再到 `文档/v1~v4/url文档v*.md` 与后端 DTO / VO 核对请求、响应。业务规则冲突时按代码、知识库现行要点、协会最新答复处理，不把原型当接口契约。
4. 本仓库是原生 WXML / WXSS / JS / JSON，无前端构建，也没有现成第三方 UI 组件库。新增页面沿用现有工具与样式，不为了单页引入框架或构建步骤。
5. 开发者工具里预览必须明确当前 API 模式。正式配置的 mock 默认关闭；指向线上时只看读取页面，**不做登录、下单、报名、捐款、支付等写操作**。

## 2. 页面搭建顺序

### 2.1 建页与路由

1. 在对应领域目录建立 `index.wxml`、`index.wxss`、`index.js`、`index.json` 四件套。
2. 在 `app.json` 注册主包页面或分包路由，同时检查首页入口、“我的”入口和页面间跳转是否指向同一真实路由。不要为了页面能预览而长期把它堆进主包。
3. 自定义导航页在 JSON 使用 `navigationStyle: "custom"`，背景色取本页面色板。例如公益捐赠页：
   ```json
   { "navigationStyle": "custom", "backgroundColor": "#fff5f7" }
   ```
4. 列表、表单、详情分别明确数据 owner；列表的筛选、分页、刷新和详情返回后的状态刷新，不能只覆盖首次进入。
5. 静态骨架完成后立即接真实 service 形状，再补 loading / empty / error / ready 四态。不要先按一套临时字段写完整页面，最后才换接口字段。

### 2.2 导航、安全区与布局

- 自定义导航通过 `utils/navigation-layout.js` 的 `calculateCustomNavLayout` 计算；公益捐赠分包由 `utils/donate/page-common.js` 的 `initNavigation(page)` 注入 `contentTop`、`navHeight`、`menuTop` 等数据。不要写死某一台手机的胶囊位置。
- 胶囊、返回按钮等导航几何使用 `px`；普通业务布局沿用 `rpx`。导航固定后，正文必须留出实际 `contentTop`，不能被导航压住。
- 固定底栏要与正文留白成对实现：公益捐赠页使用 `.donate-bottom-bar`，页面同时加 `.has-bottom`，底部留白包含 `env(safe-area-inset-bottom)`。
- 长文本允许换行，按钮和关键操作不能被挤出屏；窄屏、长标题、空数据、多行内容都要看。不要为还原一张原型截图写死整页高度。
- 原型中的规则入口矩阵先明确列数、每格宽度、间距和文字是否允许换行，再选 flex 或 grid。商城 `components/mall-header` 固定四列两行，卡卷入口单独限宽；短文字入口用 `view` + `text` 并补 `aria-role="button"`，避免原生 `button` 的默认样式干扰排版。不能只凭编译通过推断原生排版正确，也不能未经复现就归咎于某一种布局方式。

### 2.3 取数与交互

- 页面通过 `utils/data-service.js` 或相应领域 service 取数，不在 WXML 或页面 JS 中拼 URL、组装底层响应。
- 页面只消费 service 规范化后的数据。接口异常显示可重试错误态；空结果是空态，不能当接口失败。
- 分页 `page` 从 1 起，`size` 默认 10、最大 100，搜索参数为 `keyword`。加载更多要追加当前页数据并防止并发翻页，下拉刷新重新从第 1 页取。
- 重复点击写操作时用 `utils/page-action-lock.js` 的 `runPageAction(page, key, action)`；路由跳转可用 `utils/page-navigation.js` 的 `navigateOnce` / `resetPageNavigation` 防重。防重不能替代后端幂等。
- 写操作要有确认、处理中和结果反馈；失败不清空用户尚未提交的输入。表单校验、金额、实名、权限等仍以后端结果为准。

### 2.4 验收

1. 纯逻辑与契约测试优先进 `tests/`，跑 `node --test 'tests/*.test.js'`；页面结构和静态问题再跑 `node scripts/check-miniprogram.js`。后者依赖本机微信编译工具时，要区分工具缺失与真实页面错误。
2. 在微信开发者工具中按真实路由逐页看：不同尺寸、导航和安全区、四态、长文本、图片失败、返回刷新。
3. 契约测试通过不代表线上链路已验收；原生视觉看过也不代表真实接口已经跑通。汇报时分别写清“Node 测试”“开发者工具 mock 验收”“真实接口验收”。
4. 新工作流完成后按 `知识库/回归验证.md` 登记证明它的用例；不要在待办页里把“页面已画”写成“业务已端到端完成”。

## 3. 色调、字体与尺寸

**不要从公益捐赠分包复制一套粉色覆盖全站。** 当前有三组有意的层次：通用页面、首页／“我的”、公益捐赠分包。新页先归组，再沿用该组变量值；确需新色时在对应领域页记录原因。

### 3.1 全局基础（`app.wxss`）

| 用途 | 当前值 |
|---|---|
| 页面背景 / 正文 / 标题 / 弱化文字 | `#f5f7fb` / `#1f2937` / `#172033` / `#7a8394` |
| 主按钮 / 次按钮文字 | `#d83b3b`；次按钮白底、边框 `#f0c6c6` |
| 卡片 | 白底，边框 `#edf0f5`，圆角 12rpx，轻阴影 |
| 页面与控件 | `.page` padding 24rpx；按钮高 84rpx、圆角 10rpx；输入最小高 78rpx |
| 字体 | `FZDFS--GBK1-0`，正文 28rpx，区块标题 34rpx |

状态标签沿用绿 `#177245/#eef7f1`、警告 `#9b5b00/#fff4de`、危险 `#c92a2a/#ffecec`。不要为了“更鲜艳”随意增加同义状态色。

### 3.2 首页与“我的”

- 导航主色为 `#ff8cab`。
- 首页背景渐变是 `#ff8cab → #fbecea（42%）→ #fff8f6`；“我的”采用同族渐变，但中间色停在 32%，不要把两页位置混用。
- 首页快捷入口图标为 82×82rpx；标签按现有布局为 26rpx 或 32rpx，保持单行。“我的”入口图标为 72×72rpx，标签 24rpx。
- 白色内容卡承载主要信息，粉色用于导航、重点入口和少量强调；正文仍需保证对比度。

### 3.3 公益捐赠分包（`pages/donate/common.wxss`）

| 用途 | 当前值 |
|---|---|
| 页面渐变 | `#ff91ad → #ffd8e1（250rpx）→ #fff5f7（560rpx）` |
| 导航 / 主按钮 / 选中页签 / 价格 | `#ff91ad` / `#d83b50` / `#c83252` / `#d13250` |
| 正文 / 弱化文字 | `#2c2530` / `#897b82` |
| 卡片 | 白底，边框 `#f1dce2`，圆角 18rpx，padding 24rpx，下边距 20rpx |
| 成功 / 警告标签 | `#287a4a/#eaf6ee` / `#97600a/#fff3db` |
| 通知 | 文字 `#83540a`，背景 `#fff4de` |
| 尺寸 | 按钮最小高 80rpx，输入 78rpx，hero 标题 42rpx，导航标题 36rpx |

分包页面在自身 WXSS 使用 `@import "../common.wxss"`（目录深度变化时相应调整），页面根节点使用 `.donate-page`。公共改动须看分包其他页面，避免修一页、坏一组。

## 4. 图标：从原型提取，不臆造来源

### 4.1 已有资产

- 首页 P3 的 16 个入口已提取到 `assets/icons/`。`scripts/generate_pdf_style_icons.py` 的映射依次是：`register` 志愿者注册、`album` 活动相册、`activity` 志愿活动、`structure` 组织架构、`group` 志愿小组、`points` 积分兑换、`aid` 助学助困、`wish` 圆梦微心愿、`publicity` 名单公示、`crowdfunding` 项目众筹、`leader` 临时负责人申请、`download` 文件下载、`enterprise` 爱心企业、`ranking` 排行榜、`model` 榜样、`book` 公益捐书。
- 上述旧脚本包含固定 PDF 路径、页码、渲染坐标和历史目录假设，**不是任意页面的通用提取命令**。再次运行前核对 `PDF_PATH`、目标 PDF 与输出路径；不要直接运行后覆盖其他资源。
- `assets/mine-v2/questionnaire.png` 来自原型 PDF P77 的内嵌资源 `IM776.jp2`。原型没有独立问卷入口图标，这里是**明确记录的同族复用**，不是假装原型存在问卷图标。`scripts/extract_questionnaire_icon.py` 接收 PDF 参数，校验 64×64、RGBA 和透明通道，并用独占创建防止覆盖。

### 4.2 新图标流程

1. 从需求或现有入口确定原型页码，打开 PDF 核对图标边界与相邻元素。
2. 优先用 `pypdf` 提取该页内嵌原图；只有无法得到独立原图时才渲染页面并裁剪。保留原色、透明通道与宽高比，不重绘、不随意改色、不拉伸。
3. 输出到对应的 `assets/` 子目录，文件名表达用途。提取脚本须校验来源尺寸／模式，使用独占创建或明确的新增路径，禁止误覆盖不相关资源。
4. WXML 中用 `image` 搭配 `aspectFit` 和该入口组的既有尺寸；图标点击区域由外层按钮保证，不靠放大图片糊过去。
5. 在实现记录或提取脚本中登记：**原型页码、原资源名／裁剪依据、目标路径、是否同族复用**。原型没有独立图标时明确说明复用，不虚构“原型同款”。
6. 只有原型未提供且业务确需新图形时才另行设计；此时标注为新增设计，不能归入“从原型下载”。

## 5. 可复用组件与样式

### 5.1 项目自定义组件

- `components/form-questions` 是目前通用业务表单组件，`styleIsolation: isolated`。属性：`questions`、`answers`、`uploads`、`disabled`、`validationId`、`imageOnly`、`fileBusy`；事件：`answerchange`、`fileaction`。支持单选、多选、判断、单行／多行文字、附件和日期。接入时同时读组件实现与问卷领域规则，不在父页面复制一套题型渲染。
- `components/mall-header` 是商城 P29–P33 的共享头部，`active` 取 `home` / `points` / `myReviews` / `orders` / `allReviews` / `exchanges` / `rules` / `earn` / `coupons`。入口顺序与资源来源见[前端原型还原](前端原型还原.md)。组件自行读取姓名与积分、独立展示失败重试，页面显示时刷新，并隔离迟到响应；商品详情 P34 不引入它。新页面用绝对路径 `/components/mall-header/index` 注册，不能另复制一份头部导致入口和选中态漂移。
- `custom-tab-bar` 只服务首页／社区／我的三个 Tab，不是分包通用底栏。当前图标 62×62rpx、文字 24rpx、容器高 116rpx；选中色 `#ef6b76`，普通文字 `#111827`。普通分包操作按钮用页面自己的固定底栏。

### 5.2 样式类与原生组件

- 全局可复用：`app.wxss` 的 `.page`、`.section`、`.card`、`.row`、`.between`、`.muted`、`.tag`、`.primary-btn`、`.ghost-btn`、`.field`、`.input`、`.textarea`、`.picker-like`、`.list-item`。
- 公益捐赠可复用：`pages/donate/common.wxss` 中的导航、hero、卡片、标签、按钮、输入、搜索、页签、状态、封面、进度条、底部栏、选择项、信息行、通知、图片网格和时间线等 `donate-*` 类。
- 原生组件按现有页面使用 `view`、`text`、`image`、`button`、`input`、`textarea`、`picker`、`scroll-view`、`swiper` / `swiper-item`、`radio-group`、`checkbox-group` 等。项目不存在的能力不要写成“已有组件”。
- 优先组合已有类；确需页面私有样式放本页 WXSS。发现两个以上页面需要相同样式时再沉到对应公共 WXSS，并回归所有引用页。

### 5.3 页面助手

- 公益捐赠页的 `utils/donate/page-common.js` 提供 `navigationDefaults`、`initNavigation`、`requirePageLogin`、`goBack`、`confirm`、`previewImages`，以及证书关联／打开能力。`requirePageLogin` 中 mock 模式只用于本地查看，**不能据此推断真实接口免登录**。
- 通用认证、导航、防重各有现有 utils；引入前读函数契约，不在页面内另写全局锁、返回栈或胶囊计算。

## 6. 接口契约怎么对齐

### 6.1 分层顺序

1. **后端确认**：`知识库/生成/接口/<模块>.md` → `文档/v1~v4/url文档v*.md` → Controller / DTO / VO。以真实代码解决文档冲突。
2. **登记端点**：在 `utils/api-endpoints.js` 的 `ENDPOINTS.volunteer` 对应领域下添加常量；路径参数由函数生成并编码，页面不直接写请求字符串。
3. **统一传输**：请求走 `utils/request.js`，复用 token、错误和登录过期处理。新页面不要绕过它直接 `wx.request`。
4. **领域 service**：通用页面走 `utils/data-service.js`；公益捐赠走 `utils/donate/donate-service.js`，并由 normalizer 做 `payloadOf`、分页和字段规范化。真实与 mock 分支应返回同一页面模型。
5. **页面消费**：只处理交互、状态和展示；状态判断用后端状态码，不根据中文标签推断流程。

### 6.2 必须钉住的细节

| 项目 | 契约 |
|---|---|
| 方法与路径 | GET / POST / DELETE 等及 `/v/...` 路径必须与后端一致；context-path `/api` 由基址处理 |
| 分页 | `page` 从 1 起，`size` 默认 10、最大 100；读取 `records`、`total`、`page`、`size` |
| 搜索 | 使用 `keyword`，空关键字不要变成字符串 `"undefined"` |
| ID 与 Long | JSON 中按字符串处理，不用 `Number(id)`，不依赖 JavaScript 安全整数 |
| 时间 | 响应 `yyyy-MM-dd HH:mm:ss`；入参兼容 ISO `T`，按后端 DTO 传值 |
| 隐私 | 电话、受助人等字段由后端不下发明文实现；前端不能拼接或“还原”隐私 |
| 错误与权限 | 保留后端业务错误，按登录／权限结果提示；不把 403、404 或空数据都写成“网络异常” |

mock 只留在 service 层，`utils/api-mode.js` 默认 false，且 `app.js` 的显式值优先。不得因 mock 返回成功就宣称真实操作成功；真实支付必须使用后端的 prepay 参数调用微信支付，不能以前端动画代替支付结果。

### 6.3 契约测试与原生验收

- 每个 service 至少测试：HTTP 方法、路径、路径参数、查询／请求体、分页边界、响应解包与字段规范化；补充空值、异常、字符串 ID 和权限失败。
- 页面测试钉住路由注册、关键状态和防重，不用快照代替业务断言。
- 开发者工具先用本地 mock 看完整页面；需要真实写链路时改用明确授权的本地后端和测试账号。不要在正式配置上“点一下试试”。
- 报告未验证项：尤其是微信支付、物流推送、对象存储等外部渠道，不以 UI 完成代替端到端验证。

## 7. 新页交付核对单

- [ ] 业务规则、协会答复、原型页与接口来源已定位。
- [ ] 四件套、路由、入口、返回路径完整，包归属合理。
- [ ] 色调归入正确页面组，图标来源和复用关系已记录。
- [ ] 自定义导航、安全区、固定底栏、长文本和不同屏幕尺寸已检查。
- [ ] loading / empty / error / ready、分页、刷新、写操作防重已实现。
- [ ] 页面不拼 URL，ID 不转数字，隐私与状态口径符合后端。
- [ ] Node 测试和静态检查通过；开发者工具验收范围与真实接口未验证项分别写明。
- [ ] 未把本地 API 基址、临时 mock 开关或测试凭据提交进正式仓库。

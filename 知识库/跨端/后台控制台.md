# 后台控制台（`../volunteerplatform-back/`）

> 由根 `CLAUDE.md` 的「后台前端接真实接口」一节下沉而来（2026-10-17）。控制台是无构建的 React（纯 `React.createElement`），入口 `index.html` + `assets/`。

## 现行要点

- ⚠️ `index.html` 在本地打开时 `window.__API_BASE__` 指向**线上**后端——本地点的每一下都写线上库。联调用 `tools/serve_admin_local.py`（只在响应里改写基址），写操作前先确认 `window.__API_BASE__ === 'http://localhost:8080/api'`。
- 没有 error boundary：一处 render 抛错整个后台白屏；对响应 `.map` 之前先 `Array.isArray` 兜底。
- 组件的坑（不报错、只是东西不出现）：`PageHead` 的按钮 prop 是 `actions`；`Toolbar` 只认 `filters` / `actions`、不渲染 children；`Tag` 只认 `color`；`Drawer` 的 `width` 取 `'wide'` / `'xwide'`；`confirmDialog` 的原因框 resolve 的是 `{ok, reason}`；`API.put/patch/del` 第三个参数是 query。**写页面前先读组件源码**。
- 新页面共用 `assets/ui-kit.js`（`useKitPaged` / `useKitGet` / `kitActs` / `kitConfirm` …）；非 GET 成功后 `api.js` 派发 `hd:mutated`，侧栏角标据此重数。
- 验证方式：`node --check`（node 在 `~/.local/node`）只证明语法；要起本地 MySQL + Redis + api 真跑一遍写路径。

  · `page-reward-punish.js`——列表按 `reviewStatus` 分页签（**0 待初审 / 3 待终审 / 1 已通过 / 2 已驳回 / 申诉中**），开单弹窗、初审、终审、驳回、申诉受理、处置查看与提前解除。

  · `page-violations.js`——违规审核队列（待审/已通过/已驳回）。**「通过」不等于「处罚」**：通过只让记录对志愿者可见、并够格作为开单依据，页面文案与确认框都写明了这点。已通过的行可**就地开处罚单**（复用 `RewardPunishCreateModal`，带入 volunteerId/activityId/slotId/violationId 与违规类型文案），不必跳到奖惩中心再找一遍人。

- **V2 控制台第 3 批（2026-09-05）：荣誉板块**（`page-honor.js` 勋章样式 / 勋章发放审核 / 榜样 + 新建 `page-rankings.js` 排行榜）。
  · **勋章两条线分成两个菜单项**：样式审核管「长什么样、怎么才能拿到」，发放审核管「这一次要不要授给这个人」——权限不同、审的人也不同，合成一页会让只有发放审核权的人对着一堆自己动不了的样式。计数源也分开（`medalStyle`/`medalGrant`）。「已停用」用中性灰不用红：停用只是不能再发，已发出去的不受影响。
  · **排行榜的核心是把 `fromSnapshot` 摆到明面上**——后端对已结束周期「没有快照就退回实时聚合并如实回 false」，两种情况显示成同一张表格，运营就会把一份还会变的榜单当定稿发出去。故未冻结给黄色告警、已冻结给蓝色说明；**总榜从不冻结**故两条都不显示、也不给冻结按钮；「强制重算」单列一个危险确认（它丢弃已公示的名次）。**`rankType=4` 微心愿不进下拉框**——后端预留取值但显式拒绝，放进去得到的空榜单会被读成「这个月没人上榜」。
  · ⚠️ **`API.put/patch/del` 曾只收 `(path, body)`，第三个 query 参数被静默丢掉**（已修，四个写方法与 `post` 一致）。后端有一批「路径带 id、值走 `@RequestParam`」的端点（`role-models/{id}/status?status=`、`.../sort?sort=`、`medals/{id}/sort?sort=`），调用方 `API.put(path, null, {status:1})` 写法是对的、读起来也是对的，但参数根本没发出去，后端报 `MissingServletRequestParameterException` 500。**JS 少一个形参不报任何错**，多传的实参直接消失——这类缺陷只有真发一次请求才看得见。
  · **验证方式升级为「起本地 MySQL+Redis+api 真跑一遍写路径」**：上一批的教训是「语法过了不等于渲染得出来」，这一批的是「渲染出来不等于请求发对了」。上面那个 500 就是走通「新增榜样 → 上架 → 改排序 → 删除」时抓到的，当时 `node --check` 全绿、页面也渲染正常。
  · ⚠️ **`index.html` 的 `window.__API_BASE__` 在本地打开时指向的是【线上后端】**（`http://118.145.69.25/api`），这是有意的——服务器部署后，本地起静态页连线上后端是目前唯一的后台联调路径。**所以本地点的每一下都打在线上库上**，改数据前要想清楚；要打本机把那一行换成 `localhost:8080`（本机得先起 api）。⚠️ 那段注释一度写着「本地静态服务器直连后端 8080」而代码指向服务器 IP，照注释办事的人会以为自己在打本地（曾因此在联调中登进线上超管账号）——**注释与代码必须一起改**。

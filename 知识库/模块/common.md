## 职责

返回体与异常、加解密、短信通道与验证码、对象存储与上传校验、Excel、二维码、分页、分布式锁助手、Testcontainers 测试基座；**全项目唯一的 Flyway 迁移序列**也在这里（当前到 V101，清单见 `知识库/生成/迁移.md`）。

## 现行要点

- 迁移脚本只放 `src/main/resources/db/migration/`。挑号前用跨分支命令看全部分支的最大号（见下文 V27 那段）；**跑过的迁移不能原地改，只能加新号**。
- 一个迁移文件只放一条有失败可能的语句（MySQL DDL 各自隐式提交）；脚本里（**包括注释**）不能出现美元花括号占位符，Flyway 会当占位符解析。
- 最低 MySQL 8.0.17，由 `DatabaseVersionGuard` 在迁移前校验；测试容器钉 `mysql:8.0.46`。
- 通知短信模板在 `SmsNotifyTemplate` 登记（键 + 变量名 + 顺序），业务一律走 auth 的 `SmsNotifyService`。接一条新模板要改四处：业务调用、`SmsNotifyService.WIRED`、api yaml 的 `hengde.sms.templates`、`部署/api.env.example`。
- 火山短信 / TOS 对签名未审核、欠费等业务错误也回 HTTP 200，必须显式检查 `ResponseMetadata.Error`。
- 上传：`FileValidator` 校验文件头魔数并由服务端推导 MIME；「是不是本系统上传的」统一用 `FileStorageService.isOwnUpload(url, dir)`。
- 分布式锁一律走 `DistributedLockSupport.runLocked / runLockedMany`，锁在事务外取，各用各的 key 前缀。
- Excel 依赖钉了两个版本：`commons-compress` 1.27.1、`commons-io` 2.18.0——升 `poi.version` 时一起改。

## 一、范围与执行原则

- V5 交付独立监管控制面、最小运营控制台和组织侧受控连接器，不改变志愿者小程序业务流程。
- 每组织仍为独立业务库、独立配置、独立 PII 密钥、独立初始超管和独立连接器凭证；不改共享库多租户。
- 控制面不直读组织业务库，组织连接器主动出站完成登记、心跳、指标、领取命令和回执。
- 主体顺序按知识库现行口径执行：前置与契约 → 控制面地基 → 只读监管 → 白标开通 → 组织账号 → 用量计量 → 配额订单 → 验收运营。
- 切换账号默认关闭、独立解锁，不阻塞主体交付。
- 验收运营中的故障、隔离和恢复用例随对应功能批同步完成，正式运营前再做总验收。
- 每批必须带可操作的控制台切片，不累积“只有接口、运营方无界面可用”的状态。

## 四、逐阶段执行卡

### 阶段 0：前置与契约

**目标**：在写业务代码前冻结协作规则，并建立能验证双组织隔离的测试环境。

**工作项**：

1. 冻结 `control-protocol/v1` 的报文、签名规范化内容、错误码、时间、单位和版本兼容规则。
2. 编写威胁模型：伪造组织、重放命令、跨组织读取、密钥泄露、离线重投、部署参数注入和切入后台滥用。
3. 创建独立 `volunteerplatform-control` 工程，包含 `control-api`、`control-worker`、`control-console` 及独立 MySQL / Redis / Flyway 测试骨架。
4. 建立 A / B 两个本地组织测试实例与一个控制面，跨系统测试走真实 HTTP。
5. 新建 `文档/v5/url文档v5.md`，扩展现有契约脚本的文档清单；控制面另建协议契约与兼容测试。
6. 新工程建立自己的 `AGENTS.md` / `CLAUDE.md`，沿用 setter 注入、Testcontainers、迁移和并发纪律。

**完成定义**：A / B 组织与控制面测试骨架可启动；协议和威胁模型评审完成；后续阶段可直接用这套环境验证跨组织行为。

依据：`文档/v5/V5规划.md` 第六节「前置与契约批」、第九节。

### 阶段 1：控制面地基

**目标**：打通可信、可恢复、可幂等的“命令 + 本地回执”通道。

**工作项**：

1. 实现独立运营登录、防爆破、分角色权限、组织登记和只追加审计。
2. 实现一次性登记令牌、每组织非对称密钥、指纹、轮换、撤销和重新登记。
3. 建立 `ctrl_command` 与组织本地 `org_control_command_receipt`，落实幂等键、载荷哈希、租约、`attempt` 和 fencing。
4. 在业务 api 的 `control` 子包实现最小连接器，打通无业务副作用的 `PING`。
5. 控制台提供组织登记、连接状态、密钥状态和 PING 结果。

**完成定义**：伪造签名、超窗、nonce 重放、同键不同载荷、租约过期、旧 `attempt` 回写、命令重投和组织撤销均有测试；控制面重启不丢命令。

依据：`文档/v5/V5规划.md` D3、D4、第六节「控制面地基批」。

### 阶段 2：只读监管

**目标**：运营方可以看到各组织最后已知运行状态和业务聚合指标。

**工作项**：

1. 心跳上报构建版本、提交、迁移号、连接器版本和协议版本。
2. 业务统计经 owner 域只读 service 采集，复用现有 `DashboardService` 所调用的统计口径，不在控制面拼组织 SQL。
3. 指标按组织、周期和指标码唯一，以 `observed_at + revision / report_id` 防止迟到旧报文覆盖新快照。
4. 控制台提供组织列表、详情、离线标记、最后心跳和最后已知指标；不提供 PII 导出。
5. 用量字段先作为指标模型保留，真实数值在阶段 5 接入，不用页面点击量冒充实名或短信用量。

**完成定义**：A / B 同制品不同数据且不串号；迟到报文不覆盖新值；停控制面不影响组织登录、报名和签到，恢复后可补报；离线不把旧值标成实时值或把用量写成 0。

依据：`文档/v5/V5规划.md` D5、第六节「只读监管批」；`代码/hengde-volunteer-data/src/main/java/com/hengde/data/service/DashboardService.java`。

### 阶段 3：白标开通

**目标**：用固定模板从空环境开通第二个组织的服务端实例和后台控制台。

**工作项**：

1. 固化 systemd、nginx、环境配置、空库与最小权限数据库账号、初始超管、PII 密钥和连接器引导模板。
2. worker 只执行固定动作和白名单参数，不接受任意 shell / SQL；每步保存状态、摘要和重入幂等键。
3. 将品牌名称、短信签名、协议、根组织节点等改为新配置或初始化 service，不修改已执行旧迁移。
4. worker 将生成的秘密直接写入目标实例受控配置；控制面只保存引用与状态，秘密不可回读。
5. 部署组织后台静态控制台和 API 基址，配置域名 / TLS，执行健康检查和只读冒烟。
6. 失败可重试当前步骤；补偿默认停用服务并保留数据，不自动删库。
7. 将组织方提供的 AppID、域名和第三方账号列入开通检查单，微信侧办理不伪装成软件自动成功。

**完成定义**：第二组织完成迁移与只读冒烟，不出现恒德专属名称、签名或配置；重复执行不多建库或服务；失败不自动删数据。

现有改造证据：`代码/hengde-volunteer-api/src/main/resources/application.yaml` 仍有恒德短信签名；`代码/hengde-volunteer-common/src/main/resources/db/migration/V5__organization_groups_squads.sql` 仍有恒德根组织种子。

依据：`文档/v5/V5规划.md` D11、第六节「白标开通批」。

### 阶段 4：组织账号

**目标**：运营方可以远程申请账号治理动作，最终权限、有效期和会话控制必须在组织本地生效。

**工作项**：

1. 建立 `ctrl_account_shadow`，同步组织本地账号 id、用户名、状态、有效期、权限摘要和最近同步时间。
2. 实现新建、停用 / 启用、重置密码、调整有效期、授权 / 回收权限五类命令。
3. 在 auth / organization 增加受控命令 service，补齐统一有效期、首次改密和会话撤销；api 不直用 owner 域 Mapper，不伪造超管登录态。
4. 新建与重置使用组织本地一次性激活凭证；普通命令载荷、结果和日志不传密码或激活凭证明文。
5. 到期即撤销已有会话并停用，恢复需重新授权。
6. 控制面和组织本地均持久化安全审计，高危动作二次确认并记录原因。
7. 控制台提供账号影子、同步状态、五类动作和审计查询。

**完成定义**：重复命令不重复提交本地业务写入；过期账号新登录与旧会话均被拦；重置后旧会话失效且首次激活只能改密；任何日志均找不到密码或激活凭证明文。

现有改造证据：`AdminUser` 当前没有统一有效期与首次改密字段，`SaTokenConfigure.checkAdminEnabled` 当前只检查启用状态。

依据：`文档/v5/V5规划.md` D6、第六节「组织账号批」。

### 阶段 5：用量计量

**目标**：形成组织本地可持续记录、控制面可复制汇总、差异可进入对账的用量账。

**工作项**：

1. common 定义窄 `UsageMeter` 端口，system 提供组织本地持久化实现，建立 `org_control_usage_daily`。
2. 短信在真实渠道调用点记账，区分“渠道接受”和“送达”；未配置、业务失败和本地拦截不计为已接受。
3. 实名在腾讯云真实调用点记账，按实际计费结果确认；格式校验失败和本地拦截不计。
4. 对象存储按实际字节数记录当前占用，另设盘点适配器；上传次数、累计上传量和当前占用分开展示。
5. 外部调用前记录 `ATTEMPTED`，取得结果后确认；超时未闭环和供应商差额进入 `UNKNOWN / 待对账`。
6. 控制面离线时继续本地记账，恢复后按周期与来源版本幂等上报。
7. 控制台提供短信、实名、存储用量、估算标记、UNKNOWN 和对账差异。

**完成定义**：离线不丢本地账、重复上报不翻倍；渠道接受后本地崩溃的差额能进入待对账；无真实存储盘点时明确标“系统估算”，不冒充财务结算值。

依据：`文档/v5/V5规划.md` D7、第六节「用量计量批」。

### 阶段 6：配额订单

**目标**：在可信用量之上交付周年配额、预警、人工超额订单和额度包流水。

**工作项**：

1. 按组织开通周年保存周期配额、阈值和已用快照，历史周期不可被重算覆盖。
2. 实现接近阈值预警和超额告警；V5 不停止短信、实名或上传。
3. 建立 `ctrl_addon_order`，逐单人工定价，记录组织、套餐、金额分、收款人和凭证说明。
4. 建立 `ctrl_quota_credit`，记录来源订单、独立有效期、额度、消耗顺序和取消流水。
5. 订单只支持待确认、已收款（人工登记）、已取消；不接在线支付，不借用某个组织的 `trade` 表或收银台。
6. 控制台提供配额、预警、人工订单、收款登记、额度包和审计页面。

**完成定义**：周年切换不丢历史；订单重放不重复产生额度包；额度包有效期、消耗顺序和取消有用例；控制面离线时预警不被误报为实时硬限额。

依据：`文档/v5/V5规划.md` D8、D9、第六节「配额订单批」。

### 阶段 7：切换账号（默认关闭）

**当前决定**：不进入 V5 主体排期。将来如需解锁，必须重新确认哪些运营人可申请、是否需组织审批，并通过独立安全评审。

**解锁后的首版边界**：

1. 控制面申请、审批并下发一次性授权。
2. 组织本地生成短时、单次、绑定组织与操作人的 ticket；ticket 只放精确换票端点的 POST 正文。
3. 换票建立组织本地只读影子会话，不接受控制面 token，不借用超管账号。
4. 每个 `/a/**` 请求核查会话，所有写请求由后端真实拒绝。
5. 撤销覆盖未使用 ticket 与已签发会话，两端持久化审计可关联同一授权单。

**完成定义**：过期、重用、跨组织、撤销、无审批均失败；所有写请求被后端拒绝；审计能还原“谁经哪次授权对哪个组织读了什么”。

依据：`文档/v5/V5规划.md` D10、第六节「切换账号批」。

### 阶段 8：验收运营

**目标**：证明系统不仅能跑通正常流程，还能在隔离、故障、恢复和升级场景下保持安全与账务可信。

**工作项**：

1. 双组织隔离：账号、指标、命令、部署任务和未来的切换授权不能跨组织生效。
2. 故障恢复：控制面宕机、组织宕机、网络分区、控制面重启、组织重启和恢复补报。
3. 命令可靠：重复领取、重复回执、旧 `attempt`、外部副作用结果不明和待对账。
4. 密钥与数据：密钥轮换、撤销、数据库与 PII 密钥联合备份恢复。
5. 升级：协议滚动兼容、expand / contract 迁移和不可回滚判定。
6. 运营手册：开通、停用、续期、额度补购、账号重置、事故处理、导出审批与销毁审批。
7. 组织退出、欠费和停用只停用不删库；具体导出 / 销毁审批人和流程在正式运营前登记到运营手册，不写真实账号或秘密到知识库。
8. 原业务后端 parent + 14 模块全量回归、URL 契约、生成物和知识库校验全部通过。

**完成定义**：`文档/v5/V5规划.md` 第十节九项总体验收全部有证据；新控制面与组织侧跨系统用例走真实 HTTP；并发和故障用例完成变异验证。

依据：`文档/v5/V5规划.md` 第六节「验收运营批」、第七节、第十节；`知识库/横切/测试纪律.md`。

## 五、每批固定交付检查单

1. Q 前置是否已在知识库确认，是否引入新的待决项。
2. owner / 模块触点是否明确，领域依赖方向是否闭合。
3. 表、唯一键、状态机和迁移序列是否明确；控制面与业务库各自领号。
4. 本地业务写入与成功回执是否同事务，外部副作用是否有独立幂等或对账。
5. 协议版本、未知命令和滚动升级是否兼容。
6. 必跑故障、并发和变异用例是否执行并留下结果。
7. 是否交付本批控制台切片，而非只交接口。
8. 是否更新知识库现行口径、回归验证、接口契约和部署 / 运营文档。
9. 是否确认日志、控制台、测试证据和知识库均无 PII、密码、密钥及真实连接信息。

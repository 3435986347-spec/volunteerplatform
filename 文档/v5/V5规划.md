## 三、核心设计判断 D1–D12

### D1　控制面独立，业务 api 仍是单组织制品

新建同级独立仓库 / 工程 `volunteerplatform-control`，包含：

- `control-api`：运营方登录、组织登记、指标、命令、配额与审计；
- `control-worker`：部署与运维任务执行器，使用独立的最小基础设施权限；
- `control-console`：运营方最小控制台；
- 独立 MySQL / Redis、独立 Flyway 历史、独立发版与回滚。

**不把它加入业务父 POM 的 14 模块 Reactor，也不让业务 api 依赖它。** 两套系统只经版本化连接协议通信。

### D2　白标多实例＝隔离边界，不是页面换 Logo

每个组织至少有：独立业务库、独立配置、独立 PII 密钥、独立初始超管、独立连接器凭证；Redis 与对象存储可以共享基础设施，但必须使用独立逻辑库 / 桶或前缀并验证隔离。

控制面永不执行 `SELECT` 去读取组织业务库。组织间数据隔离由“不同库 + 不同凭证 + 连接器只读本组织”共同保证。

### D3　组织主动出站，控制面不反连组织管理端口

连接器部署在组织业务 api 内，启动后主动完成：登记 → 心跳 → 指标上报 → 领取命令 → 回执。

- 通信用 `control-protocol/v1` 显式版本化；未知版本 / 未知命令安全拒绝。
- 登记引导令牌一次性使用，控制面只存其哈希；登记完成后改用**每组织非对称密钥对**——组织保存私钥，控制面只存公钥与密钥指纹，支持轮换与撤销。不能用“密码哈希 + HMAC”凑验签：那样控制面根本无法取得同一个 HMAC 密钥。
- 生产必须 HTTPS；签名规范化内容固定为协议版本、组织、密钥 id、HTTP 方法、路径、正文 SHA-256、时间戳与 nonce。nonce 在控制面用 Redis 原子占位，超窗或重放直接拒绝；轮换允许短暂新旧重叠，撤销后提供重新登记流程。
- 控制面下发的命令由控制面私钥签名，组织只保存控制面公钥；组织不能伪造控制面命令，控制面也不能替组织签发其请求签名。
- 控制面或网络故障时，组织本地业务照常运行；心跳与命令恢复后继续，不阻塞报名、签到等主流程。
- 内部连接代码放 api 的 `control` 子包，沿用全局搜索的跨域聚合位置；不给 `/v/**`、`/a/**`、`/e/**` 新增一条“控制面也能登录”的旁路。

### D4　所有远程动作都是“命令 + 本地幂等回执”，不是远程改库

控制面只写 `ctrl_command`；组织连接器领取后，经 owner 域 service 执行并写本地回执，再上报结果。

中央状态：`PENDING → CLAIMED → SUCCEEDED / RETRYABLE_FAILED / FINAL_FAILED / EXPIRED`；领取必须带租约与 `attempt`，过期可回到 PENDING，旧执行者提交结果时用 attempt 做 fencing，防止慢请求覆盖新一次执行。

- 命令包含组织、类型、载荷、创建人、过期时间与幂等键；载荷不允许携带任意 SQL / shell。
- 中央唯一键＝`(org_id, command_type, idempotency_key)`，同时保存载荷哈希；同键不同载荷必须拒绝，重复点击只建一笔。
- 本地回执状态＝`RECEIVED / RUNNING / SUCCEEDED / RETRYABLE_FAILED / FINAL_FAILED`，另存 attempt、载荷哈希与错误。只有明确可重试的失败能继续使用同一命令号。
- **本地业务写入与成功回执必须同一事务提交**；唯一键防重只覆盖这组本地数据库动作。部署、外部 API、秘密展示等事务外副作用必须另有业务幂等或对账，不能统一宣称绝对“至多一次”。
- 组织崩溃后重启能根据本地回执恢复上报；孤立 RUNNING 先检查本地事务与租约：已回滚的才可重试，结果不明的进入待对账；旧 attempt 仍可能执行时，新 attempt 必须等待或拒绝，不能直接接管。结果不明的外部动作不能盲目再执行一次。
- 修改权限、重置密码、创建切换授权都必须有控制面与组织本地的**持久化安全审计**，不能只靠 V4 可丢弃的异步页面日志。

### D5　跨组织数据监管只收聚合值，不收志愿者明细

首屏只做：实例状态、版本、迁移号、最近心跳、注册志愿者数、活动场次、志愿时长、短信 / 实名 / 存储用量与配额使用率。

- 业务统计由组织 api 调 owner 域只读 service 得出；控制面不定义另一套业务口径。
- 上报报文不含姓名、手机号、身份证、详细地址、帖子正文、私信、证书文件等。
- 指标按“组织 + 周期起止 + 指标码”唯一；每次采集带 `observed_at + revision / report_id`，只在来源版本更新时覆盖，迟到旧报文不能回写新快照。counter 与 gauge 分开定义。
- 实例离线只标“最后已知值”，不把旧值当实时值，也不因离线把用量写成 0。

### D6　组织账号管理是影子记录 + 本地执行，密码永不可读

控制面保存账号影子：`org_id`、组织本地账号 id、用户名、状态、有效期、权限摘要、最近同步时间；不保存密码明文。

支持动作：新建、停用 / 启用、重置密码、调整有效期、授权 / 回收权限。规则：

- 有效期与权限必须在组织本地的登录和每次请求闸门上生效，不能只改控制面影子。
- 新建账号与重置密码统一生成本地一次性激活凭证，不在普通命令载荷、结果或日志中传新密码；凭证只允许激活一次，展示响应丢失后只能作废重发，不能重复查看。
- 重置后撤销该账号已有会话；首次激活只放行改密、退出等必要端点，改密前不放开普通后台。
- 组织侧执行经 organization / auth 明确新增的“受控命令入口”，接收命令上下文与中央操作人；不能伪造 `StpAdminUtil` 超管登录态，也不能由 api 直连 Mapper。
- 若现有能力缺“有效期”“撤销会话”或“首次改密”，先在 owner 域补齐。
- 删除账号默认不做物理删除；组织退出与数据保留另见 Q10。

### D7　计量分“消耗量”和“当前占用”，先记账再谈扣费

| 指标 | 类型 | 默认计量点 |
|---|---|---|
| 短信 | 消耗次数 | 渠道实际接受的发送请求；业务失败 / 未配置不计，接受不等于送达 |
| 实名核验 | 消耗次数 | 按腾讯云实际计费结果记录；格式校验失败与本地拦截不计 |
| 存储容量 | 当前占用（gauge） | 对象实际字节数；与上传次数分开，外部删除后要能对账 |

组织本地先落 `org_control_usage_daily`，控制面离线时仍继续本地记账；上报只是复制聚合结果。

**依赖方向必须闭合**：common 定义窄 `UsageMeter` 端口，system 提供组织本地持久化实现；短信 / 对象存储的真实调用点只依赖该端口，不让 common / auth 反向依赖 api 连接器。计量写库自身的失败策略必须显式定义，不能因一个未处理异常意外阻断业务。

**存储量不能只靠累计上传量**：删除、覆盖、直传与外部操作都会让“历史上传之和”偏离当前占用。另设独立存储盘点适配器；能列对象或取得供应商用量时才报真实值，否则明确标“系统估算”，不能冒充财务结算值。

外部调用前写 `ATTEMPTED` 留痕，取得渠道结果后再确认计费状态；超时未闭环的留痕与供应商对账差额进入 `UNKNOWN / 待对账`。这样即使“渠道已接受、本地尚未确认”时进程崩溃，也有发现入口，但不宣称绝对“不丢、不错算”。

### D8　V5 只做配额预警与人工额度订单，硬拦截移出本版

配额按组织、指标、周期保存；订单产生独立额度包流水，不改写历史用量。额度包记录来源订单、有效期、额度与消耗顺序，取消 / 重放都有明确规则。

V5 顺序固定为：**展示用量 → 接近阈值预警 → 超额告警 → 人工补购 → 对账校准**。

**硬拦截不在 V5 交付范围内。** 日聚合账不能承担付费调用前的实时并发预留；若以后要做，必须另设本地配额快照、用量事件、调用前预留 / 确认 / 释放与逐指标离线策略，并单独评审。存储直传容量限额也不能直接套短信次数模型。

### D9　增值订单不等于在线支付，控制面不能直接借某个组织的 trade

首版订单状态：待确认 / 已收款（人工登记）/ 已取消；关联组织、套餐、额度包、金额、收款人与凭证说明。

真实在线支付另开子批，前置是：运营方收款主体明确、支付渠道真实验收、退款与对账规则明确。**只复用 trade 的状态机经验，不共享组织业务交易表，也不把某个组织实例当成全平台的收银台。**

### D10　切入组织后台是独立解锁的只读能力，不接受控制面 token

Q6 未答前该功能保持关闭，且不影响“V5 主体”其余批次发布。若批准，**首版只做只读**，链路为：

1. 运营人选择组织与时限并填写原因，经所需审批后，由控制面向指定组织下发一次性授权；
2. 组织本地生成短时、单次、绑定组织与操作人的启动凭证；ticket 只放换票 POST 正文，不进 path / query / 日志；
3. 只新增一个精确路径的换票端点到公开清单，禁止通配放行；
4. 换票后建立专用只读影子账号的短时会话，权限由组织本地计算，不借用超管账号，也不直接复用控制面 token；
5. `org_control_switch_session` 保存授权单、中央操作人、范围、过期与撤销状态；每个 `/a/**` 请求都核会话，所有写请求由后端闸门真实拒绝；
6. 撤销同时作用于未使用 ticket 与已签发会话；过期、重用、跨组织、撤销均失败。控制面或网络离线时撤销只能等组织重连后同步，已签发会话最多存续到本地短 TTL，不能宣称跨网络分区即时撤销。

组织本地持久化安全审计与后续操作都带 `switch_grant_id`、中央操作人和本地请求 id；中央审计经可靠补报完成。控制面不知道组织管理员密码，组织也不接受中央会话。

### D11　一键开通由固定模板执行器完成，不提供任意脚本入口

首版沿用 systemd + nginx：组织代码经白名单校验后，worker 依次创建空库与最小权限账号、准备受控配置、通过首次受控启动完成 Flyway 迁移、部署该组织后台静态控制台与 API 基址、登记连接器、配置域名 / TLS，最后运行健康检查与只读冒烟。

- 每一步都有状态、日志摘要与可重入幂等键；失败能重试当前步骤。现有应用启动本就会执行迁移，不再额外重复执行一套。
- worker 不接收调用方传来的 shell / SQL；只允许固定动作与固定参数。
- **control-api 与控制面业务库不持久化组织数据库密码**；worker 可在部署过程中生成秘密并直接写入目标实例的受控配置，禁止落日志、命令结果与控制台，且秘密不可回读。
- 开通失败的补偿默认停用服务并保留数据，**不自动删库**。这与“版本升级回滚”不同：升级须使用向后兼容的 expand / contract 迁移；不兼容变更只能向前修复，不能承诺旧 jar 直接读新 schema。
- 组织的 PII 密钥只生成一次，并与数据库一起备份、一起恢复；控制面只展示 secret 引用与状态。
- 新组织名称、短信签名、协议、根组织节点等通过初始化 service 或新增配置生成；不改写已在恒德实例执行过的旧迁移。
- 服务端“开通成功”代表 api + 该组织后台可用；小程序仍需独立 AppID、合法域名与发布流程。

### D12　迁移、权限与配置各走各的序列

- 控制面独立库使用自己的 Flyway `V1…`；不消耗业务后端 V102 号段。
- 组织侧连接器的命令回执、用量账本等若落业务库，仍只在 common 领号；本文写“从 **V102** 起”只是当前快照，每批开工仍须跨分支查最大号、按实际开工顺序领取，并遵守一文件一条可能失败语句。
- 控制面权限码属于自己的库与登录态，不改变业务平台现行 99 个权限点。
- 所有实例化配置都有模板与启动校验；密钥、连接串、组织域名与真实账号不写入知识库。

## 四、目标架构与数据流

```text
运营人 → control-console → control-api → 控制面独立 MySQL / Redis
                                  │
                                  ├─ control-worker → 固定部署模板 / 冒烟 / 回滚
                                  │
                                  └─ 登记组织、命令、指标、配额、审计
                                               ↑
                             组织主动 HTTPS 出站：心跳 / 指标 / 领取 / 回执
                                               │
                         组织 hengde-volunteer-api（control 连接器）
                                               │
                         owner 域只读 service / 本地命令 service / 用量账本
                                               │
                                  该组织自己的业务 MySQL / Redis
```

**禁止的边**：控制面 → 组织业务库；控制面 token → 组织后台直接登录；A 组织连接器 → B 组织数据；部署 worker → 任意 shell。

## 五、数据模型草案

> 表名是规划名，不是已存在表。控制面表用 `ctrl_`；组织本地新增表用 `org_control_`，便于一眼认出边界。

### 控制面

| 表 | 管什么 | 关键约束 |
|---|---|---|
| `ctrl_operator` | 运营账号、状态、角色与有效期 | 独立登录态；部署、财务、切换、审计不混权 |
| `ctrl_role_permission` | 运营角色、权限点与分配关系 | 审批人和操作人能关联到命令、订单、授权 |
| `ctrl_instance` | 组织代码、名称、状态、协议 / 连接器版本、部署状态、最近心跳 | `org_code` 唯一；业务构建信息是最近上报快照 |
| `ctrl_instance_credential` | 一次性登记令牌哈希、组织公钥、密钥指纹、轮换与撤销 | 不存组织私钥；登记后只存公钥，不用哈希冒充 HMAC 验签 |
| `ctrl_metric_daily` | 组织业务与资源聚合指标 | 唯一键＝组织 + 周期 + 指标码；重报幂等覆盖 |
| `ctrl_command` | 远程动作、载荷哈希、状态、结果、创建人、租约、attempt 与过期时间 | 命令号全局唯一；`(org_id, command_type, idempotency_key)` 唯一，同键不同载荷拒绝 |
| `ctrl_account_shadow` | 组织后台账号影子与同步状态 | 不存密码；组织 + 本地账号 id 唯一 |
| `ctrl_quota_account` | 周期额度、已用快照、预警阈值 | 额度与用量分列，历史不被重算覆盖 |
| `ctrl_addon_order` | 超额订单与人工收款登记 | 金额统一存分；订单号唯一，不直接改写历史用量 |
| `ctrl_quota_credit` | 订单产生的额度包、有效期、消耗与取消流水 | `order_id` 唯一防重；只追加流水，明确消耗顺序 |
| `ctrl_deployment_task` | 开通步骤、当前状态、重试与结果摘要 | 同一组织的开通任务防重；不记秘密明文 |
| `ctrl_switch_grant` | 切入组织的一次性授权与审批 | 默认关闭；组织、操作人、范围、期限缺一不可 |
| `ctrl_audit_log` | 控制面敏感读与全部写操作 | 只追加；双写操作人 / 组织 / 命令 / 结果 |

### 组织本地

| 表 | 管什么 | 为什么必须在本地 |
|---|---|---|
| `org_control_command_receipt` | 命令回执、状态、attempt、载荷哈希与业务结果 | 本地业务写入与成功回执同事务；失败按类型决定能否重试 |
| `org_control_usage_daily` | 本地短信 / 实名 / 存储用量与占用 | 控制面离线仍本地记账；UNKNOWN 差额进入待对账 |
| `org_control_security_audit` | 敏感命令、账号变更、切换及结果的持久化审计 | 与业务写入同事务；V4 异步页面日志不是唯一证据 |
| `org_control_switch_ticket` | 一次性启动凭证的哈希、范围与使用状态 | 只由本组织验票；ticket 不进 URL 与日志 |
| `org_control_switch_session` | 已签发只读会话、授权单、操作人、过期与撤销 | 每个 `/a/**` 请求核查；撤销覆盖已签发会话 |

### 前置与契约批

- 明确运营方角色与首屏指标，冻结 `control-protocol/v1` 的报文、错误码、时间 / 单位、版本兼容规则。
- 写威胁模型：伪造组织、重放命令、跨组织读取、密钥泄露、离线重投、部署参数注入、切入后台滥用。
- 建两个本地组织测试实例与一个控制面；没有这条，后续“隔离”和“重试”都无法真正验证。
- 新仓库建立自己的 `AGENTS.md` / `CLAUDE.md`，沿用 setter 注入、真实 Testcontainers、迁移与并发纪律。
- 新建 `文档/v5/url文档v5.md`，并把现有契约脚本的文档清单扩展到 v5；控制面另建自己的协议契约与兼容性测试。
- 每个后续批次都按固定执行卡交付：**Q 前置 → owner / 模块触点 → 表与唯一键 → 事务边界 → 协议兼容 → 必跑故障用例 → 控制台切片 → 文档 / 部署更新**。

### 控制面地基批

- 独立控制面工程、登录、防爆破、运营角色、审计、组织登记与非对称密钥轮换 / 撤销。
- `ctrl_command` 与组织本地 `org_control_command_receipt` 协议先打通一条无业务副作用的 `PING` 命令；本批已经包含最小连接器，下一批只加心跳和指标，不重复建设。
- **完成定义**：伪造签名、时间戳超窗、nonce 重放、同键不同载荷、租约过期、旧 attempt 回写、命令重投、组织撤销均有测试；控制面重启不丢命令。

### 只读监管批

- 连接器心跳带构建、提交、迁移、协议版本；聚合统计经 owner 域只读 service。
- 控制台组织列表、详情、离线标记与最后已知指标；无 PII 导出。
- **完成定义**：A / B 两组织同制品不同数据，上报互不串号；迟到旧报文不覆盖新快照；停控制面不影响组织报名与登录；恢复后补报。

### 白标开通批

- 固化 systemd / nginx / 环境配置 / 初始超管 / PII 密钥 / 连接器引导的实例模板；worker 只执行固定步骤。
- 组织开通、品牌与根组织初始化、后台静态控制台及 API 基址、域名 / TLS、步骤重试、状态展示、只读冒烟、服务停用与数据保留式补偿。
- **完成定义**：从空环境开通第二个测试组织并完成迁移与只读冒烟；第二组织不出现恒德专属名称、签名或配置；重复执行不产生第二个库 / 服务；失败不会自动删数据。

### 组织账号批

- 账号影子同步与五类命令；组织本地补齐有效期、首次改密与审计能力。
- 控制台只对授权运营角色显示；高危动作二次确认并写原因。
- **完成定义**：重复重置 / 授权命令不重复执行本地业务写入；过期账号本地登录与已有会话都被拦；重置后旧会话失效，首次激活只能改密；任何日志都找不到密码或激活凭证明文。

### 用量计量批

- 在真实调用点记账，组织本地日聚合，控制面按周期汇总；供应商 / 本地对账差异可见。
- 短信“接受”与“送达”、实名“调用”与“计费”、存储“当前占用”与“累计上传”分开展示。
- **完成定义**：控制面离线期间本地账继续记录；重复上报不翻倍；渠道接受后本地崩溃的差额能进入 UNKNOWN / 待对账；存储有真实盘点能力时核对当前占用，没有时清楚标“系统估算”。

### 配额订单批

- 周期配额、阈值预警、额度包流水、人工超额订单与收款登记；所有金额与额度操作留审计。
- 硬拦截和在线支付均不在本批；Q4 只决定未来是否另立硬配额项目，不在本版预埋一套不能正确工作的拦截器。
- **完成定义**：周期切换不丢历史；订单重放不重复产生额度包；额度包有效期、消耗顺序与取消规则有用例；预警与控制面离线互不误导。

### 切换账号批

- 仅在 Q6 有明确答案后实现；默认无权限、默认关闭，首版只读，需单独授权与安全评审。
- owner 域提供专用只读影子账号与会话级闸门；精确换票路径、POST 正文 ticket、已签发会话撤销和可靠安全审计同时交付。
- **完成定义**：过期、重用、跨组织、撤销、无审批均失败；只读会话的任何写请求都被后端真实拒绝；两端持久化审计能还原“谁经哪次授权对哪个组织读了什么”。

### 验收运营批

- 双组织隔离、控制面宕机、组织宕机、网络分区、密钥轮换、命令重投、兼容升级与不可回滚判定、数据库 + PII 密钥联合备份恢复各做一次。
- 形成运营手册：开通、停用、续期、额度补购、账号重置、切换授权、事故处理与数据保留。
- 业务后端原 14 模块全量回归仍必须绿；新增组织侧迁移 / Controller 后跑契约、生成与知识库校验。

## 七、跨批次承重条款

1. **控制面故障不能拖垮组织业务。** 除经明确批准并本地可判的配额外，所有监管 / 命令 / 上报失败都只记状态与告警，不阻塞组织主流程。
2. **命令允许至少一次投递，本地数据库动作靠事务 + 唯一键防重。** 中央与本地都保存载荷哈希，领取有租约与 attempt；事务外副作用另做幂等或对账，不能靠“网络一般不会重发”。复核读遵守当前读纪律。
3. **不跨组织传 PII 与秘密。** 指标报文采用白名单字段；日志、异常、审计、测试证据都不能打印凭证、密码、密钥或完整报文。敏感命令与切换使用组织本地持久化安全审计并可靠补报，V4 可丢弃的异步页面日志不能充当唯一证据。
4. **部署 worker 无任意命令能力。** 固定模板、参数白名单、最小系统权限、逐步幂等；回滚不自动删库。
5. **业务口径只在 owner 域。** 控制面与 api 连接器不拼外域 SQL；新统计先由 owner 域提供只读接口。
6. **计量单位与周期显式保存。** 次数、字节、金额分分别存储；时区固定 Asia/Shanghai；日 / 年边界与迟到数据规则在协议里，不靠显示层猜。
7. **V5 不做付费调用硬拦截。** 本版只计量、预警与人工订单；未来若启用，必须另建实时预留 / 确认 / 释放模型，并有并发、离线、重试与供应商对账测试。
8. **切换后台不信任中央 token。** 一次性、短时、单组织、可撤销、双审计；首版只读，必须由后端会话级权限执行，撤销覆盖已签发会话。
9. **测试沿用 `@SpringBootTest` + Testcontainers MySQL / Redis。** 不写纯 Mockito 单测代替真实协议；至少一套 api HTTP 全流程用例覆盖登记 → 心跳 → 命令 → 回执。
10. **并发与故障用例必须真的跑到各结局。** 命令重投、配额并发、切换验票、部署重试都要变异验证；单独跑绿不等于全量跑绿。
11. **协议兼容优先于临时改字段。** 连接器与控制面可不同版本滚动升级；未知命令安全失败，旧版本不能被新载荷误执行。
12. **文档不记录真实连接信息。** 组织地址、账号、密钥只进部署人员的受控配置；知识库只写协议与规则。

| Q8 | Row 85 必须监管哪些指标、允许多大延迟？ | 首屏用本规划 D5 的聚合值；分钟级心跳、日级业务指标 | 只读监管批前 |
| Q9 | 新组织的小程序主体、AppID、域名、第三方账号由谁准备？ | 组织方提供；V5 只自动服务端，微信侧列检查单 | 白标真实开通前 |
| Q10 | 组织退出 / 欠费 / 停用后数据保留多久，谁批准导出或销毁？ | 停用不删库；导出与销毁另行审批 | 生产正式运营前 |

## 九、工程边界与依赖

```text
volunteerplatform-control（新独立工程）
├── control-api       → 控制面独立 MySQL / Redis
├── control-worker    → 固定部署动作与最小基础设施权限
└── control-console   → 运营方控制台

现有业务后端（每组织一套）
└── hengde-volunteer-api
    └── control 连接器 → owner 域只读 service / 本地命令与用量 service
```

- 新业务仓库不挂进业务父 POM；现有 Reactor 仍为 parent + 14 模块。
- 连接器优先放 api，不新建第 15 个业务模块；如果组织本地命令需要 owner 域补能力，先在 owner 域实现，再由 api 调 service。
- 控制面与组织侧各自建测试启动类与容器配置；跨系统验收必须起真实 HTTP，而不是把两个 service 在同一个 Spring 上下文里直接互调。
- 新增业务 Controller / 迁移 / 权限时，仍执行现有 URL 契约、生成物与知识库规则；控制面另建自己的接口契约与检查脚本。

## 十、V5 总体验收口径

| 验收项 | 必须证明的事 |
|---|---|
| 双组织隔离 | A 的账号、指标、命令、切换授权与部署任务不能作用于 B |
| 控制面离线 | 组织登录、报名、签到、积分等主流程不受影响；恢复后指标与命令能续传 |
| 命令可靠 | 重复领取、重复回执、控制面重试、组织重启不重复提交本地数据库动作；旧 attempt 不能覆盖新结果；外部副作用有待对账路径 |
| 账号安全 | 任何地方读不到原密码；重置、有效期、权限在组织本地真正生效 |
| 计量可信 | 控制面离线时本地账继续、重报不翻倍；崩溃差额进入 UNKNOWN / 待对账；存储有真实盘点时核对占用，否则标系统估算 |
| 配额可控 | 周期与订单幂等；额度包有效期、消耗与取消可追踪；V5 不宣称提供硬拦截 |
| 部署可重入 | 重复开通不多建；失败可重试；开通失败补偿不自动删除组织数据；升级是否可回滚有明确判定 |
| 切换可追责 | 一次性、短时、单组织、只读、可撤销；撤销覆盖已签发会话，两端持久化审计能拼出完整操作链 |
| 不泄漏 | 协议、日志、控制台、导出与知识库均无 PII、密码、密钥与真实连接信息 |
| 原系统不退化 | 业务后端全量测试、URL 契约、生成物与知识库校验全部通过 |

## 十一、明确不属于 V5

- 单组织小程序与协会后台的业务补欠、页面改版及既有十二项待协会答复事项；
- 纸质证书、i志愿证书、仓库管理、评优评先、会员费与组织业务积分权益；
- 单实例微服务化、Spring Cloud、Kubernetes、XXL-Job；
- 未经 Q5 与真实渠道验收的在线收费；需要实时预留与离线策略的付费调用硬拦截；
- 未经 Q6 与安全评审的切入组织后台；任何可写切换或“超级管理员随意进入任何组织”；
- 以共享数据库或中央 PII 汇总换取实现便利。

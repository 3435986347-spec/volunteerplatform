恒德志愿者小程序 · 协会答复五（2026年10月16日）带来的小程序改动（2026年10月17日）

说明：
- 协会 10 月 16 日逐条答复了 9 月 27 日那份问题清单，后端已按答复改完（迁移 V94–V100）。下面是小程序要跟着改 / 新做的地方。
- 接口路径与参数见后端仓库 文档/v3/url文档v3.md 末尾「协会答复五（2026-10-16）落地」一节；本地起后端后 Knife4j（/api/doc.html）里也有。
- 视觉与页面结构仍由小程序侧决定，下面只说「要展示什么、调哪个接口、有哪些口径」。


======================================
一、积分商城（乙-5 / 丙-3 / 丁-2）
======================================
1. 兑换不再审核
   - 纯积分的单，点「兑换」即成功：POST /v/donate/orders 返回的单状态直接是「待领取」（自提）或「待发货」（快递），不再有「待审核」。
   - 有现金要付的单，付款成功即进入待领取 / 待发货。
   - 志愿者只能取消「待支付」的单（DELETE /v/donate/orders/{id}）；成功之后的单不显示「取消」，改为提示「如需取消请联系协会」。
   - 协会在后台取消时会发短信告知，单子变为「已取消」，积分、卷自动退回，付过的现金原路退回。

2. 领取方式每件商品自己定
   - 商品详情 GET /v/donate/goods/{id} 新出：
       allowPickup / allowExpress：这件商品能不能自提、能不能快递（只显示能用的那几种）；
       pickupPoints：可选的自提点列表（名称、地址、电话、开放时间），自提时让用户选一个；
       expressFeeFen / expressPoints：这件商品的快递费（现金，分）与运费积分，可能只有其中一个；都有时让用户二选一；
       virtualGoods：虚拟商品（只能自提）。
   - 下单时自提要带 pickupPointId（从 pickupPoints 里选的那个）；商品没有自提点列表时不用带。

3. 虚拟商品
   - 商品页不显示兑换二维码（后端也不下发）。
   - 兑换成功后，在「我的兑换」详情 GET /v/donate/orders/{id} 里有 virtualGoods=true 与 redeemQrUrl（兑换二维码图片），在详情页展示出来。

4. 规格可以是纯现金
   - 规格的所需积分可能是 0：只有金额＝纯现金，只有积分＝纯积分，都有＝积分 + 现金。纯现金的单不能用卷。


======================================
二、协会证书（乙-1 / 乙-2）
======================================
1. 证书列表 GET /v/honor/certificates 加了可选参数 category：
   activity 志愿活动 / pair 助学助困 / wish 微心愿 / book 公益捐书 / crowdfund 项目众筹 —— 对应原型 P83 的页签。
   每条多了 category、categoryLabel、sourceTitle（项目 / 心愿 / 捐书活动的名称）。
2. 捐赠证书什么时候有：
   结对：协会确认结对成功时（证书上写「结对成功」，不写金额）；
   微心愿：心愿实现时；
   公益捐书 / 众筹捐物：协会核对出合格物资时（一个包裹一张；全部不合格的没有证书——对应原型 P98「未审核的没有证书」）；
   众筹捐款：钱到账时（退款后证书撤销）。
3. 「查看证书」按钮：GET /v/honor/certificates/by-ref?bizRef=…
   - 捐书记录 / 众筹捐物记录：bizRef = book:运单id 或 cf-goods:运单id；
   - 众筹捐款记录：cf-money:捐款id；
   - 心愿详情（我认领的）：wish:认领id；
   - 结对：pair:结对登记id。
   返回 null 表示还没有证书（还没核对 / 还没实现 / 还没到账），按钮置灰或不显示。
   预览 / 下载沿用 /v/honor/certificates/{id}/preview 与 /file。


======================================
三、助学结对（丙-2）
======================================
1. 项目详情 GET /v/donate/pair-projects/{id} 新出受助人一块（原型 P47 / P48 / P102）：
   beneficiaryName（姓名）、beneficiaryGender（1男 2女）、beneficiaryAge、beneficiarySchool、beneficiaryGrade、reportOrgName（上报单位），
   beneficiaryMasked=true 表示姓名 / 学校已打 *（后端已经打好，直接显示即可；只有这个项目上已成立结对的人看到全文）。
   这些字段都可能为空（改造前的项目没填），为空时这一块不显示。
2. 活动动态（发放凭证）：GET /v/donate/pair-projects/{id}/updates（分页，时间倒序），每条有内容、图片、发生时间。
   与「受助方来信」是两回事：来信可能是写给某个人的私信，动态一律公开。


======================================
四、项目众筹（丙-1）
======================================
- 每个项目只收一种：acceptMoney=true 的只显示「我要捐款」，acceptGoods=true 的只显示「我要捐物」。
- 只收物的项目 targetAmount 可能是 0，不要显示「已筹 / 目标」的进度条。
- 答协会的问题：「志愿者码」就是 i志愿 平台的个人码（我的资料里上传的那张），小程序里的叫法保持「i志愿者码」即可。


======================================
五、捐款发票（丁-5）
======================================
- 捐款详情 / 结对中心里的每笔捐款多了：
    invoiceFileReady：发票文件已上传，可以下载；
    completed / progressLabel：「待支付 / 已到账，待开票 / 已完结 / 已取消 / 已退款」，订单状态按 progressLabel 显示。
- 下载发票：GET /v/donate/donations/{id}/invoice-file 返回一个约 2 分钟有效的链接，拿到即用 wx.downloadFile + wx.openDocument 打开（PDF）
  或预览图片；不要把链接存下来，过期就失效了。


======================================
六、注销冷静期（乙-4）
======================================
- 申请注销（POST /v/user/deactivation）后，后端会让当前登录失效——小程序收到成功后直接回到登录页。
- 冷静期内再登录（任何一种方式），后端自动撤销注销、账号恢复正常；登录结果里 deactivationCancelled=true，
  这时弹一句提示：「你在 7 天冷静期内重新登录，注销申请已撤销，账号恢复正常」。
- 冷静期过了再登录会被拒（账号已注销）。


======================================
七、物流（甲-3）
======================================
- 协会只买了快递100 的「查询」：用户打开快递单号时才去查（后端在有人查看时按刷新间隔调用），没有推送、也不发订阅消息。
- 小程序在运单 / 兑换详情里照常显示轨迹即可；轨迹为空时显示「暂无物流信息」。


======================================
八、微心愿（丁-7）
======================================
- 看心愿详情仍然要已验手机号（现状）；后端会记下谁看过、用的哪个号，给协会看。小程序不用改，但心愿详情页如果有「未绑定手机号」的引导，保持即可。
